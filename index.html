How the detection task works

Each case takes a clean episode and applies one typed transform to its plan — substitute an object, drop a subgoal, redirect a destination, redo a completed action, stall. The model is stepped through the resulting video in order and at each second sees only the past: an eight-second window at one frame per second. It answers either SILENT or FLAG_ERROR with a class name.

Scoring is exact-match on the class name. Flagging at the right moment with the wrong label counts as a false positive, not a hit — a strict choice, but it is what exposes the dominant failure mode: the model very often reacts at the right instant and then misnames what it saw.

The model is shown a clean cut with no banners, subtitles or timeline. The annotated cut on the results page exists only so a human can follow along.

A note on what these videos show

Two rendering defects were found and fixed before this round. VirtualHome sets an object's state absolutely but toggles its visual, so a setup command asserting a state an object already held inverted its appearance permanently — in six of nineteen episodes, opening the fridge rendered as closing it and switching a lamp off rendered as switching it on. Separately, the egocentric camera looked straight ahead during manipulations, leaving the acted-on object at the frame edge; it now aims at the target, and at the destination when something is being set down.

This matters for reading the results. Correcting the inversion moved detection of repetition from 0 of 6 to 3 of 6 with no regressions in that class, while every other class moved in both directions — and repetition is exactly the class whose cases turn on seeing a device get re-toggled. An earlier write-up concluded that repetition failure was a memory limit rather than a legibility one; that conclusion rested on a comparison this bug had confounded, and it has been retracted.

The overall total barely moved (15 → 16 of 27). With one run per case and a stochastic model, that difference is noise; the class-specific, one-directional shift is the part worth reporting.
